# Сенокос — правила проекта

Казуальная веб-игра про сенокос: косарь идёт за пальцем, коса бьёт сама раз в секунду.
Сеттинг нейтральный: без лора «Сайылыка» и якутских терминов.

План и принятые решения — `docs/План прототипа.md` (в конце — правки после игры автора и раздел
про PvP). Готово: косьба; скошенное лежит и сохнет на месте, грабли сгребают сухое сено в тюк,
тюк выгружается в стог; пять улучшений; конец дня с итогами.

С 12.11.2026 коса и грабли — отдельные инструменты: в руках что-то одно, меняется кнопкой
(автор: «а то имбово»). Оба сразу — только после «синтеза» (длина косы и ширина граблей на
максимуме). С косой косарь медленнее, но только она бьёт; того, кто с граблями, прикрывает
тюк: удар сначала выбивает сено, по ногам — только по пустому тюку.

PvP: против бота и с друзьями по сети, до четырёх игроков, все против всех; у каждого свой
стог и свой цвет, поле растёт с числом игроков (и ещё на 15 %). В центре — ларёк: общий котёл
сена, 15 кг на игрока; когда он полон, ружьё получает тот, кто сдал больше всех (одно на день;
стреляет только с косой в руках; подстреленный отлетает и долго лежит). У стога — будка: 25 кг
сена — собака-сторож. Сено в ларёк и будку уходит, только если рядом остановиться. Локации (луг,
огороды с заборами, река с мостами) выбирает зерно; в одиночку — всегда луг, втроём — без реки. Сервер для игры по сети пока запускается на
Макбуке автора (`npm run host`); в интернете его нет.

Дальше автор хочет: комнаты через бота, отдельный сервер игры в интернете, мини-карту,
прокачку внешности. Погода (шаг 3 плана) отложена.

Игра в сети: https://tevakaraka.github.io/senokos/ (`npm run deploy`), в Telegram — @Sayilyk_Bot.

## Нельзя нарушать

- **Симуляция считает одинаково на любом устройстве.** В `src/sim/` разрешены только `+ − × ÷ %`
  и `Math.sqrt floor ceil round trunc abs sign min max imul fround`. Никаких `Math.sin/cos/random`,
  оператора `**`, часов и браузера. Синус и косинус — из `dmath.ts`. Это проверяет
  `tests/purity.test.ts`. После любой правки симуляции — `npm test` и `npm run xengine`.
- TypeScript только «стираемый» (без `enum`), импорты с расширением `.ts`: Node запускает
  `src/sim` напрямую, без сборки.
- Набор чисел баланса (`tuning.ts`) замораживается на старте забега. Новое число баланса
  обязательно добавить в `tuningValues()`, иначе оно не попадёт в хеш записи.
- Число и места кустиков — правила игры. Уровни качества меняют только картинку.
- В игре список игроков `game.players`; свой — номер 0. Ввод — байт на игрока за шаг:
  0…64 — направление, 65…67 — выбор перка, плюс 128 — кнопка смены инструмента.
- События шага у игрока (`swing`, `cutFrom/cutTo`, `rakeFrom/rakeTo`, `rakedKg`, `pickedKg`,
  `stolenKg`, `unloadedKg`, `leveled`, `swapped`, `hitBy`) и буферы `cutIdx`, `rakeIdx` в хеш
  состояния не входят.
- Выбор перка — отдельный ввод (`CHOICE_BASE + номер`), время он не двигает; пока кто-то выбирает,
  время стоит для всех. Прогоны ботов — через `src/sim/autoplay.ts`.
- Счёт — `stacked` (кража его уменьшает), опыт для перков — `delivered` (только растёт).
- В спорный шаг игроки ходят по очереди (`tick % n`) — не давать никому вечного первенства.
- Игра по сети — «шаг в шаг» (`src/net/lockstep.ts`): по сети идёт только ввод, считает каждая
  копия сама. Поэтому всё, что влияет на исход, обязано жить в `src/sim/` и зависеть только от
  зерна и ввода. Сервер (`tools/server.mjs`) игру не считает и не должен.
- Версия обмена записана дважды и обязана совпадать: `NET_PROTOCOL` в `src/net/protocol.ts`
  и `PROTOCOL` в `tools/server.mjs` (как и `MAX_PLAYERS`). Это проверяет `tests/net.test.ts`.
- Цвет игрока закреплён за его номером (`PLAYER_COLORS`) и одинаков на всех экранах.
- Где что в симуляции: `combat.ts` — удары и их последствия (рана, ноги, тюк, выстрел, укус),
  `arms.ts` — магазин и ружьё, `dog.ts` — будка и собака, `world.ts` — препятствия (общие для
  людей и собак), `nav.ts` — карта проходимости и поиск пути (для бота и для проверки, что поле
  проходимо), `gen.ts` — поле и локации.
- Всё быстрое (полёт от выстрела) двигать мелкими шажками: иначе тело проскакивает тонкий забор.
- Сено в ларёк и будку отдаёт только стоящий (`p.still >= dwellTicks`), свой стог берёт его
  и на ходу. Правила «по направлению движения» не возвращать: из-за них тюк пропадал у тех, кто
  бежал через центр, а у своего стога сено застревало.
- Любой удар — коса, выстрел, укус — проверяет забор (`fenced` в `world.ts`).
- Новое правило мало покрыть тестами: прогнать его сценарием «как сыграет человек» и на ботах
  (`npm run bot -- 30 pvp`). Так нашлись дыры, которые тесты пропустили: бот сдавал в ларёк
  по килограмму, собака сама забегала под косу.
- Тесты, где важна открытая местность, явно берут луг: `createGame(seed, tuning, n, MAP_MEADOW)`
  (иначе зерно может выбрать реку или огороды).
- Запас для ввода по сети назначает сервер (`delayFor` в `tools/server.mjs`) по замеру связи
  игроков и присылает в `start` — один на всех; у клиентов свой запас брать нельзя.
- Туннель в интернет (`cloudflared … --url http://localhost:4173`) запускать только по прямой
  просьбе автора: он открывает игру всем, у кого есть ссылка. Адрес каждый раз новый.
- Ввод по сети идёт двумя дорогами сразу: напрямую между игроками (`src/net/p2p.ts`, WebRTC)
  и через сервер. `Lockstep.receive` берёт первый пришедший и отбрасывает повтор — на этом всё
  держится, не ломать. Сервер для прямой связи только пересылает «визитки» (`sig`).
- Опубликованная игра ищет сервер по `public/net.json` (вне git). Сменился адрес туннеля —
  обновить файл и выложить заново, иначе кнопки «С друзьями» в боте не будет.
- Сервер игры можно запустить на любой машине: `node tools/host.mjs --public=<внешний адрес>`
  (нужны `dist/` и `tools/{host,server}.mjs`) — тогда он называет игрокам этот адрес. Этот
  репозиторий публичный: адреса и описания чьих-либо серверов сюда не писать.
- Коммиты — только по команде автора.
- Интерфейс и комментарии в коде — на русском.

## Команды

```bash
npm run dev        # http://localhost:5173
npm run build && npm run preview   # собранная версия в Wi-Fi, порт 4173
npm run host       # сборка + сервер для игры с друзьями на том же порту 4173 (вместо preview)
npm test           # правила, одинаковость, чистота
npm run typecheck
npm run xengine    # V8 против JavaScriptCore
npm run bot        # статистика бота по зёрнам; `npm run bot -- 30 pvp` — два бота друг против друга
```

## Подводные камни

- Системный `jsc` не открывает файлы по пути с кириллицей («МОИ ПРОЕКТЫ»), поэтому
  `tools/xengine.mjs` запускает его из папки `dist-sim/` с одним именем файла.
- Проверка картинки в панели браузера: `window.senokos.freeze(true)`, затем `advance(n)`,
  `advanceToSwing(n)` или `advanceTo('hit' | 'hurt' | 'steal' | 'swing', после)`. Так кадры идут
  и при скрытой панели, где `requestAnimationFrame` стоит. Настоящий цикл (ввод с клавиш, карточки,
  итоги) там же гоняется через `senokos.frameAt(мс)`. Координаты `zoom` — в пикселях скриншота
  (750×1624 при окне 375×812).
- В скрытой панели стоят и CSS-анимации: карточки и итоги выглядят полупрозрачными, вспышка
  не гаснет. Перед снимком отключить: стиль `* { animation: none !important; transition: none !important }`.
- После правки бота эталон самопроверки устаревает: `node tools/make-selftest.mjs` (или `npm run build`).
- Режим: `?mode=pvp&go=1` — сразу в бой; `&auto=1` — за игрока тоже бот.
- Чтобы Мак не уснул, пока работает сервер игры (автор играет удалённо): `caffeinate -i -s -w <pid сервера>`
  — удержание снимается само, когда сервер остановится. Настройки сна (`pmset`) не трогать.
- Игра по сети проверяется в нескольких вкладках панели: `?mode=net&auto=1&room=любое` в каждой,
  в первой нажать «Начать», затем в каждой `senokos.pump(секунд, ускорение)` — кадры идут без
  `requestAnimationFrame`, сеть успевает. `senokos.sync()` покажет число шагов, сколько сверок
  состояния сошлось и не разошлись ли копии. Комнату для проверки брать не `main` — там могут
  играть люди.
- В проекте нет `@types/node`: тесты не импортируют `node:*`. Сервер написан на `.mjs`,
  его типы для тестов — в `tools/server.d.mts`.
- Настоящий WebRTC на этом Маке не проверить: весь трафик идёт через VPN (сетевой интерфейс
  198.18.0.1), и два конца не соединяются даже внутри одной страницы — ни в панели браузера,
  ни в Chrome без окна. Логика прямой связи проверяется на подставном канале
  (`tests/p2p.test.ts`); настоящую связь проверяет автор на телефонах.
- В `ffmpeg` на этом Маке нет фильтра `drawtext`.
- Звуки и музыка в `public/audio/` — из библиотеки автора, права подтверждены им (2026-11-12): можно публиковать.
